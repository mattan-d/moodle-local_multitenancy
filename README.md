# local_multitenancy — ריבוי דיירים ב־Moodle

תוסף מקומי ל־Moodle שמאפשר להפעיל **מספר דיירים (טננטים)** מאותו קוד אתר, כאשר לכל דייר יש בדרך כלל **מסד נתונים נפרד** ו־**moodledata (`dataroot`) נפרד**. האתר הראשי (האב) משמש לניהול רשימת הדיירים ולכתיבת קובץ `registry.php` שממנו ה־bootstrap בוחר את הדייר בכל בקשה.

**מצב בשימוש:** Alpha (גרסה 0.1.0). מתאים לסביבות פיתוח ובדיקות; בייצור יש לבחון היטב אבטחה, גיבויים והרשאות.

---

## דרישות

- **Moodle:** לפחות גרסת ליבה התואמת ל־`$plugin->requires` ב־`version.php` (נכון לכתיבה זו: Moodle 4.1 ומעלה).
- **מסד נתונים:** יצירת סכימה אוטומטית והעתקת DB מהאב נתמכים למשפחת **MySQL/MariaDB** (`mysqli`, `mariadb`, `auroramysql`) ול־**PostgreSQL** (`pgsql`) — כולל `pg_dump`/`psql` ב-CLI וגם fallback ב-PHP כשאין כלי שורת פקודה (יצירת סכימה מ-`information_schema` והעתקת נתונים). פורט/socket של PostgreSQL נלקחים מ-`$CFG->dboptions` (נשמרים גם לדייר בעת יצירה).
- **Hooks:** התוסף משתמש ב־hooks של ליבת Moodle (בין השאר `before_standard_top_of_body_html_generation` לעמוד התחברות ומידורים).

---

## התקנה

1. העתק את התיקייה `multitenancy` לתוך `moodle/local/` כך שהנתיב יהיה:
   `moodle/local/multitenancy/`
2. ב־**ניהול האתר → הודעות** הרץ עדכון/התקנה של התוספים (או `php admin/cli/upgrade.php`).
3. הקצה למנהלים את היכולת **`local/multitenancy:manage`** (ברירת מחדל: ארכיטיפ Manager).

## הגדרת `config.php` (חובה)

לפני השורה:

```php
require_once(__DIR__ . '/lib/setup.php');
```

הוסף (התאם נתיב לתיקיית registry — חייב להתאים להגדרה בממשק הניהול):

```php
if (!defined('MULTITENANCY_REGISTRY_DIR')) {
    define('MULTITENANCY_REGISTRY_DIR', $CFG->dataroot . '/multitenancy');
}
require_once(__DIR__ . '/local/multitenancy/bootstrap.php');
local_multitenancy_bootstrap($CFG);
```

**הערות חשובות:**

- אל תשתמש ב־`$CFG->dirroot` בשורות האלה — Moodle מגדיר אותו רק בתוך `setup.php`. השתמש ב־`__DIR__` לנתיב ל־`bootstrap.php`.
- צור את תיקיית ה־registry בדיסק (`mkdir`), וודא שמשתמש שרת האינטרנט יכול **לקרוא ולכתוב** שם (שם ייווצר `registry.php`).

קטע זה מופיע גם ב־**ניהול האתר → תוספים → תוספים מקומיים → ריבוי דיירים** תחת "קטע ל־config.php".

---

## הגדרה בממשק הניהול

1. **ניהול האתר → תוספים → תוספים מקומיים → ריבוי דיירים**
   - **תיקיית registry:** נתיב מוחלט זהה ל־`MULTITENANCY_REGISTRY_DIR` ב־`config.php`.
2. **ניהול האתר → תוספים מקומיים → ניהול דיירים** (או מהעמוד של התוסף)
   - הוסף דייר, ערוך או מחק.
   - **ניהול משתמשים (כל הדיירים)** — מסך מרכזי עם חיפוש/סינון לפי דייר, שם משתמש, דוא"ל ועוד; כולל עמודת שם הדייר. כפתור **הוספת משתמש** יוצר חשבון חדש בדייר שנבחר (לא באתר האב). מעמודת **פעולות** (אייקון הגדרות) ניתן להעביר משתמש למסד נתונים של דייר אחר (העתקת רשומת `user` והסרה רכה מהמקור; ללא הרשמות לקורסים).
   - אם שינית הגדרות — לחץ **בנייה מחדש של קובץ registry** (או שמור דייר מחדש) כדי לעדכן את `registry.php` ואת קבצי ה־gateway.
3. **ניהול האתר → תוספים מקומיים → ניהול קודי דיירים מותרים**
   - הזן רשימת קודים אפשריים (קוד אחד בכל שורה).
   - במסך **הוספת דייר**, שדה **קוד דייר** יוצג כרשימה נפתחת מתוך רשימה זו.

---

## הוספת דייר

בטופס "הוספת דייר" ממלאים בעיקר:

- **קוד דייר (`shortcode`):** מזהה קצר, ייחודי, לשימוש ב־URL וב־CLI (`MOODLE_TENANT`). מומלץ אותיות באנגלית, מספרים וקו תחתון.
- אם הוגדרה רשימת "קודי דיירים מותרים" — שדה קוד הדייר נבחר מתוך dropdown (במקום הקלדה חופשית במסך הוספה).
- **שם לתצוגה**, **מופעל**, **הצג בדף התחברות**, **סדר מיון**.
- **מידורים:** תוכן HTML (עורך Moodle) שמוצג בראש כל עמוד בזמן גלישה בדייר — באנר בסגנון Jumbotron. נשמר ב־registry בעת שמירת הדייר.

### אתחול מסד הדייר מהאב

אם מסמנים **"אתחול DB דייר מהאתר הראשי אם הוא ריק"**:

- בעת שמירה, אם למסד הדייר **אין עדיין טבלאות**, התוסף יכול להעתיק את מסד Moodle של האב לתוך מסד הדייר.
- אפשר לבחור האם **להעתיק גם קורסים וכל נתוני הקורסים**, או רק סביבת דף הבית (ללא שאר הקורסים).

אם למסד הדייר כבר יש טבלאות — האתחול ידולג.

**הקמה ברקע (adhoc):** יצירת דייר חדש (או שמירה עם "אתחול DB מהאב") **לא חוסמת את הדפדפן**. לאחר שמירה מוצגת הודעה שההקמה בתור; המשימה רצה דרך cron (`php admin/cli/cron.php` או cron של השרת). בעמוד ניהול דיירים מוצגת עמודת **הקמה** (בתור / בתהליך / הושלם / נכשל).

## כניסה לדייר מהדפדפן (Gateway)

לכל דייר מופעל נוצרת תיקייה בשרת:

`local/multitenancy/users/{קוד_הדייר}/`

עם קובץ `index.php` שנוצר אוטומטית (stub). כתובת הכניסה הטיפוסית:

`https://<האתר-שלך>/local/multitenancy/users/<קוד>/`

(או עם קידומת נתיב אם Moodle בתת־תיקייה.)

**מה קורה בכניסה:**

- ה־stub מגדיר קבוע `LOCAL_MULTITENANCY_ENTRY_SHORTCODE`, טוען `config.php`, וה־bootstrap בוחר את הדייר ומגדיר עוגיות (קוד דייר + בסיס ציבורי של האתר) כדי שבדיקות ה־URL של Moodle יתאימו ל־`SCRIPT_NAME`.
- לאחר מכן מתבצעת הפניה (303) לשורש האתר הציבורי.

**יציאה מהדייר:**

- `/local/multitenancy/leave.php` — מנקה עוגיות ומחזיר לדף הבית של האתר.
- בהתנתקות (`login/logout.php`) עוגיות הדייר מתנקות אוטומטית.

בעמוד ההתחברות הראשי (`/login/index.php`), בתוך `login-container` (מעל טופס ההתחברות):

1. **רשימה נפתחת (dropdown)** של דיירים **מופעלים** עם **"הצג בדף התחברות"**, לפי `sortorder` — **רק באתר האב** (לא בדף התחברות של דייר); בחירה מעבירה ל־gateway.
2. **כרטיס דייר נוכחי** (כשיש עוגיית דייר פעילה) — שם, מזהה/קוד, וקישור «יציאה מהדייר»; מוצג בלוגין של הדייר, לא ברשימת הבחירה.

---

## מצבי זיהוי (תקציר)

1. **כניסה דרך Gateway** — הנתיב `/local/multitenancy/users/{קוד}/` קובע דייר (אם קיים ומופעל ב־registry).
2. **עוגייה דביקה** — לאחר בחירה, בקשות נוספות על אותו host משתמשות בעוגייה.
3. **מיפוי לפי HTTP Host** — אם ב־registry מוגדר מפתח host, ניתן לנתב לפי `HTTP_HOST` (למשל תת־דומיין אמיתי לכל דייר).

דפי ניהול של התוסף (`manage.php`, `edit.php`, `delete.php`, `users_manage.php`, `allowed_shortcodes.php` ועוד) והגדרות התוסף תחת `admin/settings.php?section=local_multitenancy` **תמיד** נשארים על **קונפיג האתר האב**, גם אם עוגיית דייר פעילה.

## סנכרון מנהלי מערכת (Cron)

משימה מתוזמנת של התוסף (`Sync parent site administrators to tenants`) רצה כל **15 דקות** (ברירת מחדל) ומסנכרנת את כל משתמשי **מנהל המערכת** של האתר הראשי (`siteadmins`) לכל דייר **מופעל** שמסד הנתונים שלו כבר קיים:

- יצירה או עדכון משתמש בדייר לפי `username` (כולל hash סיסמה — אותה התחברות כמו באב).
- הוספת מזהי המשתמשים ל־`siteadmins` בדייר (מיזוג עם רשימה קיימת, בלי להסיר מנהלים מקומיים).

הפעלה ידנית:

```bash
php admin/cli/cron.php
```

ניתן לשנות תזמון ב־**ניהול האתר → שרת → משימות מתוזמנות**.

## שורת פקודה (CLI)

לפני הרצת סקריפטי Moodle ב־CLI עבור דייר מסוים:

```bash
export MOODLE_TENANT=קוד_הדייר
php admin/cli/cron.php
```

(או כל פקודת CLI אחרת.) ללא המשתנה — רץ בהקשר של האתר הראשי לפי `config.php`.

### אבחון Gateway (דף לבן וכו')

מתיקיית שורש Moodle:

```bash
php local/multitenancy/cli/diagnose_gateway.php --shortcode=CODE
```

או `-s CODE`. הסקריפט בודק registry, רשומת דייר, נתיבים, קובץ gateway, חיבור DB (mysql-family + pgsql) וכתובת צפויה בדפדפן.

## מחיקת דייר

מחיקה בממשק **מסירה את הרשומה והמיפוי** — **לא** מוחקת את מסד הנתונים של הדייר ולא את תיקיית ה־`dataroot`. יש לנקות ידנית אם נדרש.

## הרשאות ואבטחה

- ניהול דיירים דורש **`local/multitenancy:manage`** (סיכונים: הגדרות אתר, אובדן נתונים, XSS).
- ודא שרק מנהלים מהימנים ניגשים לניהול ולתיקיית ה־registry.

## פתרון בעיות קצר

| תסמין | מה לבדוק |
|--------|-----------|
| אין `registry.php` / שגיאות כתיבה | נתיב `MULTITENANCY_REGISTRY_DIR`, הרשאות כתיבה, שמירת דייר או "בנייה מחדש של registry". |
| 404 בכניסה ל־gateway | קוד דייר לא קיים, דייר מושבת, או registry לא עודכן. |
| דף לבן | הרץ `diagnose_gateway.php`, בדוק לוגי PHP/שרת, HTTPS ועוגיות `Secure`. |
| אתחול DB נכשל | ודא דרייבר נתמך (MySQL-family/pgsql); בדוק הרשאות משתמש DB ליצירת סכימה והעתקה. |
